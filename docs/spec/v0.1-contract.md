# crust v0.1 — contract

The behavioural spec for v0.1, organised by module. Each section maps to one test file under `tests/`. Implementations are green when every test passes. **No feature lands without a test first.**

---

## 1. `Pipeline<T>` — `src/pipeline.ts`

Test file: `tests/pipeline.test.ts`.

The unifying abstraction. Every source produces one, every transform takes one and returns one, every sink consumes one.

### Construction

- `Pipeline.of(source)` accepts `T[]`, `AsyncIterable<T>`, or `ReadableStream<T>`.
- A fresh `Pipeline` is lazy: nothing executes until a terminal op (`.collect()`, `.text()`, etc.) is awaited.

### Chaining ops

- `.pipe(stage)` — `stage` may be:
  - a function `(x: T) => U | Promise<U>` (returns `Pipeline<U>`)
  - another `Pipeline<U>` (concatenates)
  - an async iterable (consumed in order)
- `.map(fn)`, `.filter(fn)` — standard array semantics, applied lazily per item.
- `.reduce(fn, init)` — terminal; returns `Promise<A>`.

### Terminal ops

- `.collect()` → `Promise<T[]>` — drains the pipeline into an array.
- `.text()` → `Promise<string>` — joins items with `\n` (items must be `string`-castable).
- `.lines()` → `AsyncIterable<T>` — yields items one at a time without buffering.
- `.json<U>()` → `Promise<U>` — concats items then `JSON.parse`s.

### Laziness invariant

- `Pipeline.of([1,2,3]).map(x => { sideEffect(); return x; })` must NOT call `sideEffect` until a terminal op runs.

## 2. Sources — `src/sources.ts`

Test file: `tests/sources.test.ts`.

- `range(start, end)` — inclusive integer range. Returns `Pipeline<number>`. Empty when `start > end`.
- `glob(pattern)` — file paths matching the glob, relative to CWD. Returns `Pipeline<string>`. Supports `*`, `**`, `?`, `[abc]`. Empty pipeline on zero matches.
- `read(path)` — read a file. Returns a `Pipeline<string>` of lines, with `.text()` and `.json()` available on the same object.
- `GET(url, opts?)` — HTTP GET. Returns `Pipeline<Response>` with a single item.

## 3. Transforms — `src/transforms.ts`

Test file: `tests/transforms.test.ts`.

All HTTP transforms operate item-by-item on the upstream stream.

- `POST(url, opts?)` — POSTs each upstream item as the request body. String → text body; object → JSON body with `content-type: application/json`. `Buffer`/`Uint8Array` → raw body. Returns `Pipeline<Response>`.
- `PUT(url, opts?)`, `PATCH(url, opts?)`, `DELETE(url, opts?)` — same shape as POST.
- `expect(matcher)` — assertion stage. Matcher may be:
  - a number (`expect(201)`) — fails the pipeline if any `Response.status` differs.
  - a string `"2xx"` / `"3xx"` / `"4xx"` / `"5xx"` — fails on out-of-class status.
  - a predicate `(item) => boolean` — fails on `false`.
  - Pipeline rejects with `ExpectError` (one error wins, includes failing item + index).
- `parallel(n, fn)` — runs `fn` over upstream items with at most `n` in-flight concurrently. **Preserves input order in the output.**

## 4. Sinks — `src/sinks.ts`

Test file: `tests/sinks.test.ts`.

- `write(path)` — writes each item as a line to `path`. Creates parent dirs.
- `dest(dir)` — for `Pipeline<{ path, contents }>` items (vinyl-ish): write each to `dir/<basename>`.
- `stats()` — terminal; returns `{ count, durationMs, status: Record<number, number>, p50, p95, p99 }` for `Pipeline<Response>`.

## 5. Lexer — `src/lexer.ts`

Test file: `tests/lexer.test.ts`.

- `tokenize(line)` — splits on top-level `|`, respecting double quotes, single quotes, and parens. Returns `{ kind: "stage", text }[]`.
- `classify(stage)` — returns `{ kind, ... }`:
  - `glob` if `text` contains `*`, `?`, or `[…]` and isn't quoted
  - `range` if matches `range(…)`
  - `lambda` if starts with `(` and contains `=>`
  - `http` if matches `^(GET|POST|PUT|PATCH|DELETE) `
  - `function` if first token is registered via `crust.fn()`
  - `shell` otherwise (default — runs via `sh -c`)

## Future stretch (not in v0.1 contract)

- **Stdlib utility transforms / terminal ops** — small wins, candidates for v0.1.5:
  - `uuid` source — `range(0, 99) | uuid | asCsv`
  - `base64.encode` / `base64.decode` transforms
  - `ssh.keygen` source — `range(0, 5) | ssh.keygen | dest keys/`
  - `.asCsv()` / `.asTsv()` / `.asJson()` terminal ops alongside `.text()` / `.json()`
  - `hash.sha256` / `hash.md5` transforms
  - `jwt.sign` / `jwt.verify`
  - `sql` source/transform via `Bun.sql` — `sql "SELECT * FROM users" | asCsv`, `fixtures/*.json | sql.insert users | expect ok`. Connection string from `DATABASE_URL`.
  - `serve` sink via `Bun.serve` — `./public | serve :3000` (static), `serve :3000 (req => new Response("hi"))` (handler), and `range(0,3).reusePorts(() => serve :3000 handler)` (multi-worker with SO_REUSEPORT). Pairs naturally with the `parallel` / `reusePorts` primitives.
- **Auto-expose global npm packages as shell commands.** v0.1 ships explicit `crust.fn("name", handler)` registration in `init.ts`. v0.1.5 may add: any package found under `~/.bun/install/global/node_modules/` or the npm global prefix is callable as `<pkg> [args]`, defaulting to invoking the package's `default` export.
- **`|>` operator + `[0..9]` range literal** via custom Bun loader.
- **Unifying shell `|` parser with `Pipeline<T>`** — currently the parser already builds a single `Pipeline`; this is for any leftover seams discovered in implementation.
- **`$(...)` command substitution & backticks** in cross-stage position (currently work only inside a single `sh -c` shell stage).
